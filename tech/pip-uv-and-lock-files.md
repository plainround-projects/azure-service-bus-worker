# pip, uv, virtual environments and lock files

*How the exact set of Python packages is installed and pinned. Pinned here: pip 26.2.2, uv 0.11 (to write the locks), setuptools 75 or newer, pip-audit 2.10.1.*

## What it is

**pip** is the program that installs Python packages. A **lock file** lists the exact version, and a fingerprint (a hash), of every package that must be installed, including the packages those packages need. **uv** is a fast tool from the same ecosystem that can resolve dependencies and write that lock file. **pip-audit** checks the locked versions against a database of known security problems.

## Why this repository uses it

Production grade means the same bytes everywhere. The lock files fix every package, direct and indirect, with its hash; CI checks them for known vulnerabilities.

## Where it appears

| File | What it does with it |
|---|---|
| `requirements.lock` | Runtime packages, exact versions and hashes. |
| `requirements-dev.lock` | Runtime plus the development tools. |
| `Makefile` | Creates `.venv`, installs from the lock, `make audit`. |
| `pyproject.toml` | Ranges the locks are generated from; the build backend. |

## How it works underneath

`pyproject.toml` says what the project needs in broad terms: `flask>=3.1,<4`. Resolving turns that into exact choices: every package at one version, with its own dependencies. `uv pip compile --generate-hashes` does that once and writes `requirements.lock`, where each line is `name==version` followed by `--hash=sha256:...` for each downloadable file.

`pip install --require-hashes -r requirements.lock` then refuses to install anything whose downloaded file does not match a listed hash. So every machine installs exactly the same bytes, and a tampered package is rejected.

`python -m venv .venv` creates the virtual environment folder. `pip install --no-deps -e .` installs this project itself in **editable** mode (the installed package points at the source folder, so edits take effect at once) without pulling dependencies again.

## Walkthrough of this repository's use

### The ranges the locks come from

```toml
dependencies = [
    "azure-identity>=1.19,<2",
    "azure-servicebus>=7.13,<8",
]
```

These are the two libraries the code imports, with allowed ranges: `azure-identity>=1.19,<2` means 1.19 or newer but below 2.

### A lock file line

```text
azure-identity==1.27.0 \
    --hash=sha256:6a4c50e25e8e9a47b324a95ad024897e56cb3c6241e0094e93b126a2bf71edc5 \
    --hash=sha256:92fd2a93c0d2f777dac6c04e5fd7d5734f6643582b983544ef66b4575844e46d
```

Each package is pinned to one version, followed by the SHA-256 hash of each downloadable file. The first lines of the file record the exact command that made it.

### Installing from the lock

```make
$(STAMP): requirements-dev.lock pyproject.toml
	$(PYTHON) -m venv $(VENV)
	$(VENV)/bin/pip install -q --require-hashes -r requirements-dev.lock
	$(VENV)/bin/pip install -q --no-deps -e .
	touch $@
```

`$(STAMP)` is `.venv/.installed`. Make rebuilds it only when the lock file or `pyproject.toml` is newer. `python -m venv .venv` creates the virtual environment. `pip install -q --require-hashes -r requirements-dev.lock` installs every pinned package and refuses any whose hash differs. `pip install -q --no-deps -e .` installs this project in editable mode without touching the dependencies. `touch $@` creates the stamp file (`$@` is the target name).

### The audit

```make
audit: $(STAMP) ## check the locked dependencies for known vulnerabilities
	$(VENV)/bin/pip-audit --no-deps --disable-pip -r requirements-dev.lock
```

`--no-deps` stops pip-audit from resolving again, `--disable-pip` tells it not to use pip, and `-r requirements-dev.lock` checks the locked versions against a vulnerability database. It needs network access, so it runs in CI and in `make audit`, not in `make test`.

### How the locks are made

The locks were generated with `uv pip compile pyproject.toml --generate-hashes --python-version 3.12 -o requirements.lock` (and with `--extra dev` for the dev lock). `--python-version 3.12` makes the result valid for the oldest supported Python.

## Try it yourself

Look at the first lines of the lock file.

```bash
head -8 requirements.lock
```

You should see something like this:

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --generate-hashes --python-version 3.12 -o requirements.lock
azure-core==1.41.0 \
    --hash=sha256:522b4011e8180b1a3dcd2024396a4e7fe9ac37fb8597db47163d230b5efe892d \
    --hash=sha256:f46ff5dfcd230f25cf1c19e8a34b8dc08a337b2503e268bb600a16c00db8ad5a
    # via
    #   azure-identity
    #   azure-servicebus
```

Count the packages in the runtime and dev locks.

```bash
grep -c '^[a-z]' requirements.lock; grep -c '^[a-z]' requirements-dev.lock
```

You should see something like this:

```text
16
53
```

See what the virtual environment holds.

```bash
.venv/bin/pip --version; .venv/bin/pip list 2>/dev/null | grep -E '^(flask|gunicorn|azure-identity) '
```

You should see something like this:

```text
pip 26.2.2 from ./.venv/lib/python3.13/site-packages/pip (python 3.13)
azure-identity           1.27.0
```

## Mistakes people make

- Installing without the lock file, so each machine gets slightly different versions. The Makefile always installs from the lock.
- Editing the lock file by hand. Regenerate it with `uv pip compile`.
- Forgetting `--generate-hashes`, which removes the tamper protection.
- Mixing the system Python's packages with the project's. Use the `.venv`.
- Ignoring `pip-audit` findings. CI runs it so a vulnerable pin is visible.

## Check yourself

1. **What does a lock file add over `pyproject.toml`?**
   Answer: Exact versions and hashes of every package, including indirect ones.

2. **What does `--require-hashes` do?**
   Answer: It makes pip refuse any package file whose hash is not listed.

3. **What does `pip install -e .` do?**
   Answer: It installs the project in editable mode so the installed copy is the source folder.

4. **Why use `--no-deps` for the project itself?**
   Answer: The dependencies were already installed from the lock file.

5. **What does pip-audit check?**
   Answer: Whether any locked package version has a published vulnerability.
